# タスク

## 目標

Change Viewer のドメインモデルと外部境界を定義し、入力検証・Git 読み取り・VS Code 表示を分離して後続タスクが同じ契約を利用できる状態にする。

## 背景

現状は `src/extension.ts` に Hello World コマンドだけがあり、レビュー入力、CU、Git 差分、警告、選択状態を表すモデルやサービス境界は存在しない。以降の実装が VS Code API や Git コマンドに直接依存すると、ドメインロジックの単体検証と差分照合の再利用が難しくなる。

依存関係: なし。後続の全タスクが依存する基盤タスクである。

## 受け入れ条件

- `src/input.schema.json` と `docs/spec.md` の主要概念（Review Route、CU、Edit、SourceLocation、ContextReference、Git 差分、警告、未割当差分）を表す型が定義されている。
- JSON 構造を扱うコア層が `vscode` API、Git プロセス、ファイルシステムへ直接依存しない。
- Git の内容取得・差分計算と、VS Code の Webview・Tree View・エディタ操作を差し替え可能な境界として定義する。
- レビューセッションが「入力を検証済み」「Git 内容を読み込み済み」「CU 照合済み」「表示中の選択」を扱える契約になっている。
- 後続タスクが不要な共有ユーティリティや UI 固有の型を新規に作らずに実装を開始できる。

## 必要な検証

- コア型と境界の単体テストを追加し、正常な最小入力、追加・削除・名前変更のファイル、複数 Edit を表現できることを確認する。
- `npm run check-types` を実行する。
- `npm run lint` を実行する。
- VS Code API や Git 実装を import していないコアモジュールを確認する。

## リスク

HIGH

### 理由

既存の雛形にないアーキテクチャ境界を導入し、後続タスクすべての依存先を決めるため。ここで責務を誤ると、Git・検証・表示の変更が相互に波及する。

## 対象外

- 入力 JSON の実際のパース・検証。
- Git のコミット解決、差分計算、blob 読み込み。
- Webview、Tree View、コマンドの具体的な UI 実装。
- `docs/spec.md` の変更。
