# タスク

## 目標

選択されたワークスペースの Git リポジトリから、`baseCommit` と `targetCommit` のツリー・blob・直接差分を仕様どおり取得する。

## 背景

差分は merge-base や Working Tree を使わず、指定された2コミットを直接比較する。差分計算は外部 diff・textconv に依存せず、Myers アルゴリズムと 50% の名前変更検出を固定する。実ソースと差分本文の正本は Git の実内容である。

依存関係: 001、003。002 の形式検証を通過した入力を受け、005 へ差分と blob の読み取り結果を渡す。

## 受け入れ条件

- `baseCommit` と `targetCommit` が対象リポジトリ内の commit に解決でき、完全長・小文字 IDでない場合はレビュー開始前にエラーになる。
- Working Tree の未コミット変更を結果へ含めず、merge-base を使わずに指定コミット間だけを比較する。
- テキスト変更、追加、削除、名前変更、名前変更を伴う変更を旧パス → 新パスの1ファイルとして扱う。50%未満の類似度で Git が名前変更と判定しないものは削除・追加として扱う。
- Myers の行差分を取得し、旧版・新版の変更行位置と実本文を保持する。
- バイナリ、権限変更、行差分のない名前変更など、行で表せない変更をファイル・変更種別・パスの概要として返す。
- Git blob のバイト列をそのまま取得し、LF/CRLF と最終行の改行有無を保持できる。
- Git のユーザー設定や textconv によって行位置や本文が変わらない。

## 必要な検証

- 一時 Git リポジトリを使い、分岐後の2コミットを比較して merge-base や Working Tree の変更が混入しないことを確認する。
- 追加・削除・離れた複数変更・名前変更・類似度 50% 前後・バイナリ・権限変更・CRLF・末尾改行なしを fixture 化する。
- 40 桁と 64 桁の object format を実行環境が扱える場合は両方を確認し、未対応環境は未検証として記録する。
- Git コマンド失敗、存在しない commit、対象外パス、blob 読み取り失敗をエラーとして扱う。
- `npm run check-types`、`npm run lint`、`npm test` を実行する。

## リスク

HIGH

### 理由

Git CLI からリポジトリの内容を取得する処理であり、比較対象の取り違えや名前変更・バイナリ判定の誤りはレビュー結果全体を壊すため。

## 対象外

- CU の Edit 範囲を実変更行へ割り当てる処理。
- Review Route や Webview の表示。
- Working Tree をレビュー対象に含める機能。
