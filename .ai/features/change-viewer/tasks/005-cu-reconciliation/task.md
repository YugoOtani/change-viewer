# タスク

## 目標

入力された CU の FilePair・Edit 範囲を Git の実差分へ照合し、CU ごとの表示対象・警告・未割当差分を決定する。

## 背景

CU に含める変更箇所は JSON が定め、拡張は Git hunk や関数の範囲から再生成しない。指定範囲に実変更行以外が含まれていても、重なる実変更行だけを CU に表示する。CU 同士の重複は警告せず、未割当差分からは一度だけ差し引く必要がある。

依存関係: 001、002、004。006〜009 が参照するレビュー用の確定データを提供する。

## 受け入れ条件

- 追加・削除・変更の各 EditSide を対応するコミット側の実変更行へ照合する。
- ファイル不存在、指定範囲に実変更行以外が含まれる場合は CU 警告を付け、重なる実変更行だけを表示対象にする。
- 重なる実変更行がない場合は、CU を警告付きで残し「該当する実差分なし」と指定位置を返す。
- 1 CU の離れた複数 Edit を保持し、同じ変更行を複数 CU が指しても警告しない。
- 実差分から全 CU の指定範囲と重なる行の和集合を差し引き、CU の重複割当を未割当一覧へ重複表示しない。
- CU の範囲外の実変更行、CU に属さないテキスト変更、行で表せない変更を未割当差分として返す。
- 「経路未割当 CU」と「未割当差分」を別の結果として保持する。

## 必要な検証

- 離れた複数 Edit、同じ行を共有する2 CU、範囲の一部だけ一致、全部不一致、ファイル追加・削除を単体テストする。
- CU の重複を未割当から一度だけ除外できること、CU 範囲外の行が残ることを確認する。
- バイナリ・権限変更・行差分のない名前変更が概要として未割当一覧に出ることを確認する。
- 実 Git fixture を使った結合テストで、差分本文が 004 の実内容から生成され、入力 JSON の本文を参照していないことを確認する。
- `npm run check-types`、`npm run lint`、`npm test` を実行する。

## リスク

MEDIUM

### 理由

重複、追加・削除側の行番号、未割当集合の扱いを含むドメインロジックであり、CU に割り当てる行の誤りが表示と警告の両方に影響するため。

## 対象外

- Git 差分アルゴリズム、名前変更検出、blob 読み取り。
- Review Route の UI 上での「経路未割当 CU」表示。
- 差分本文の HTML/CSS 表示。
