# タスク

## 目標

`docs/spec.md` の受け入れ条件を再現できる実 Git リポジトリと入力 JSON の fixture を整備し、実装全体を自動検証と手動検証で確認する。

## 背景

Change Viewer は固定コミット、離れた Edit、CU の重複、未割当差分、バイナリ・権限変更、無効参照、大規模差分など、通常のサンプルだけでは確認できない境界を持つ。モックだけでは Git の直接比較や VS Code の表示品質を確認できない。

依存関係: 010。必要に応じて 002〜009 の各タスクから fixture を再利用し、総合確認用に最小限の実リポジトリケースをまとめる。

## 受け入れ条件

- 固定コミット2件、正しい入力 JSON、複数 Route を使って、merge-base や Working Tree に依存しない直接差分と Route 切り替えを確認できる。
- 1ファイル内の離れた変更、同じ行を共有する2 CU、CU 外変更、未割当テキスト、バイナリ、権限変更を1つ以上の fixture で再現できる。
- 必須項目欠落、型違い、Route 0 件、未知 CU、重複 ID、リポジトリ外パス、存在しない commit・親コードをエラー／警告として確認できる。
- 削除のみ CU、追加削除混在 CU、親コード B → C → B、大規模 CU の概要表示・全文展開を確認できる。
- 自動検証結果に実行コマンド、PASS / FAIL / NOT RUN、未検証事項を記録できる。
- 手動検証では Extension Development Host 上の Route、Tree、差分、通常エディタ、通知、警告、選択同期を確認する手順が残っている。

## 必要な検証

- `npm run check-types`、`npm run lint`、`npm test`、必要な fixture / 統合テストを実行する。
- `git diff --check` を実行する。
- Extension Development Host で受け入れ条件の操作を順に確認し、結果をタスクまたはレビュー記録へ残す。
- 実行できない環境依存のケースは PASS とせず NOT RUN として理由を記録する。

## リスク

MEDIUM

### 理由

実装済み機能を順に実行したときの処理漏れや、モックでは見えない Git・VS Code 間の不整合を発見する最終確認である。fixture が不足すると、検証できない仕様が残る。

## 対象外

- 受け入れ確認の結果を理由にした仕様変更。
- 既存機能と無関係なテスト基盤の刷新。
- 実装不備の修正そのもの（見つかった不備は該当タスクへ戻す）。
