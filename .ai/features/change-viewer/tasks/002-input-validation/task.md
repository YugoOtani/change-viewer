# タスク

## 目標

入力 JSON をレビュー開始前に読み込み、スキーマ違反と仕様で定められた相互参照・パス・範囲のエラーを特定して、エラー時はレビューを開始しないようにする。

## 背景

入力の構造は `src/input.schema.json`、意味と追加検証は `docs/spec.md` が正本である。構造検証だけでは重複 ID、未知の CU、リポジトリ外パス、SourceLocation の逆順などを検出できないため、構文・構造・意味の検証結果を分けて扱う必要がある。

依存関係: 001。004 の Git リポジトリ存在確認とは分離し、ここでは commit ID の形式を検証し、実在確認は 004 で行う。

## 受け入れ条件

- JSON 構文エラー、`schemaVersion` の未対応、必須項目欠落、型違い、余分な項目、空の Review Route、空文字列、Edit の両側欠落を検出する。
- CU ID と Route ID の重複、Route から参照された未知の CU ID、絶対パス、空パス、`..` によるルート外参照、未対応のパス区切りを検出する。
- `SourceLocation` の `startLine > endLine`、不正な行番号、FilePair の両側欠落を検出する。
- commit ID は対象リポジトリの object format に適合する完全長の小文字 16 進文字列として検証する。
- 検証エラーには JSON の該当位置と理由を保持し、エラーが1件でもある場合は後続のレビューセッションを生成しない。
- Route に一度も現れない CU はエラーにせず、005 以降で「経路未割当 CU」として扱える。

## 必要な検証

- `src/input.schema.json` の正常例と、各エラー条件を最小限の fixture で単体テストする。
- 40 桁・64 桁の小文字 ID が有効で、短い ID と大文字を含む ID が無効になることを確認する。
- 同一 CU の複数 Route 参照、同一 Route 内の繰り返し、Route 未参照 CU が許可されることを確認する。
- 入力エラー時にレビュー開始処理へ進まないことを結合テストで確認する。
- `npm run check-types`、`npm run lint`、`npm test` を実行する。

## リスク

MEDIUM

### 理由

入力契約とレビュー開始可否を決めるドメインロジックであり、誤検知は正しいレビューを開けなくし、見逃しは不正な参照や誤った表示につながるため。

## 対象外

- commit が実際に対象リポジトリに存在するかの確認。
- Git blob と実差分に対する CU 範囲の照合。
- 入力エラーの最終的な通知・Webview 表示のデザイン。
- `.vscode/change-viewer.json` の構造決定。
