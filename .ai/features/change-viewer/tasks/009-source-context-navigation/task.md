# タスク

## 目標

CU 選択時の実ソース表示、親コードの左右エディタグループ表示、インライン説明、親コード階層の移動を VS Code の通常エディタで実装する。

## 背景

CU は原則として対象コミットの実ソースを開き、削除行だけの CU は基準コミットの削除前ソースを開く。CU と最小の親コードは左右のエディタグループで同時に見られ、親コードの外側への移動では横の親コード表示だけを切り替え、CU の選択を維持する。ソース本文は書き換えない。

依存関係: 001、004、005、007、008。SourceLocation の存在確認と警告、選択状態の購読を担当し、006 の Route code step も同じソース移動処理を利用する。

## 受け入れ条件

- 追加・変更を含む CU は targetCommit、削除行だけの CU は baseCommit のソースを開き、CU の該当行を強調する。
- 追加と削除の両方を含む CU は差分 Webview に新旧を表示し、通常エディタは targetCommit 側を開く。
- `contextChain` を直近の親コードから外側へ扱い、親コードを別ファイル・別コミット・同一ファイルの別位置でも元ファイルのまま開く。
- 親コードを左右のエディタグループで表示し、親コードが存在しない場合は横のファイルを開かない。
- CU の実ソースと親コードの各位置の近くに summary を表示し、選択で reason / description を展開できる。ソースファイルの内容は変更しない。
- CU A を選択したまま、親コード B → 外側 C → B と切り替えられ、CU A の選択と差分表示位置を維持する。
- 存在しないファイル・範囲外行・不正な参照には参照単位の警告を付け、移動操作を無効にして残りのレビューを続ける。

## 必要な検証

- 追加・変更 CU、削除のみ CU、追加削除混在 CU、複数 Edit、親コードなし、同一ファイル親コード、別ファイル親コードを fixture で確認する。
- 親コード B → C → B の状態遷移で CU 選択と差分強調が維持されることを単体・結合テストする。
- 入力の先頭行（1 行目）が VS Code の Range の 0 行目に変換されることを確認する。
- 不存在参照で操作が無効になり、ソース本文が変更されていないことを確認する。
- Extension Development Host で左右エディタグループ、行強調、インライン説明、親コード切り替えを目視確認する。

## リスク

HIGH

### 理由

Git の revision に応じて VS Code のエディタ・エディタグループ・装飾 API を操作する処理であり、削除行や 1 始まり／0 始まりの変換を誤ると誤ファイル・誤行を開くため。

## 対象外

- Git blob・差分の取得。
- 差分 Webview の本文レイアウト。
- ソースファイルそのものへの書き込み。
