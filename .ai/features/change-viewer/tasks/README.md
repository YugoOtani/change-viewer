# Change Viewer 実装タスク

`docs/spec.md` に定められた Change Viewer を、既存の VS Code 拡張の雛形から実装するためのタスク分割です。

## 進行順

基本的には次の順で進めます。

```text
001 外部処理の抽象化・ドメイン契約
  ├─ 002 入力 JSON の構文・構造・参照検証
  ├─ 003 入力元・ワークスペース解決
  └─ 004 Git リポジトリ読み取りと直接差分
       └─ 005 CU と実差分の照合・未割当差分
            ├─ 006 Review Route Webview
            ├─ 007 Explorer Tree View と選択状態
            ├─ 008 差分 Webview
            └─ 009 実ソース・親コードナビゲーション
                 └─ 010 拡張機能の統合・ライフサイクル
                      └─ 011 受け入れ確認用フィクスチャと総合検証
```

002 と 004 は 001 完了後に並行して設計できるが、003 のレビュー開始処理は 002 と 004 の契約に依存する。005 以降は、表示対象を確定できる 005 の完了後に進める。実装時に共有インターフェースが変わる場合は、並行実装を避けて先に契約を更新する。

## 現時点で仕様から確定できない事項

- `.vscode/change-viewer.json` の JSON 構造、入力 JSON との関係、検出・更新の契機が `docs/spec.md` にない。
- エディタで開いた JSON に対するコマンド ID、JSON 以外を開いている場合の具体的なエラー UI が定義されていない。
- 入力エラーの表示形式（通知、Diagnostics、専用 Webview）と JSON 内の位置の示し方が定義されていない。
- 差分 Webview の正確な HTML/CSS、色、展開コントロールの表現が定義されていない。

これらは実装者が暗黙に仕様化せず、該当タスクの着手時に決定事項として記録する。
