# タスク

## 目標

エディタで開いている入力 JSON と対象ワークスペースを解決し、手動起動・複数ワークスペース・設定ファイルの自動検出を、レビュー開始処理へ渡せるようにする。

## 背景

仕様では、エディタで開いている JSON からコマンドを実行でき、手動起動時は現在選択中のワークスペースを対象とする。複数ワークスペースでは起動時に対象フォルダを選ぶ。また、各ワークスペースの `.vscode/change-viewer.json` の検出・更新時にはレビューを開く通知を出すが、画面を自動で開かない。

依存関係: 001。入力内容の検証は 002、Git の commit 実在確認は 004 に委譲する。設定ファイルの形式は仕様未定義のため、着手時に決定事項として確定する。

## 受け入れ条件

- アクティブな JSON 文書から入力を読み取り、対象ワークスペースを解決してレビュー開始サービスへ渡す。
- ワークスペースが1つの場合はそのワークスペース、複数の場合は対象フォルダ選択を経て選んだワークスペースを使う。
- 対象ワークスペースのルートを Git・パス検証・ソース移動へ一貫して渡し、カレントディレクトリや別ワークスペースへ暗黙に切り替えない。
- `.vscode/change-viewer.json` を検出または更新したときは通知だけを行い、レビュー Webview を自動表示しない。
- 入力ソースがない、対象ワークスペースがない、JSON を読めない場合にレビューを開始せず、呼び出し元が扱えるエラー結果を返す。
- コマンド登録と自動検出の購読解除が拡張のライフサイクルに結び付いている。

## 必要な検証

- 単一ワークスペース、複数ワークスペース、ワークスペースなし、アクティブ文書なしのテストを追加する。
- `.vscode/change-viewer.json` の検出・更新通知でレビュー画面が開かれないことを、形式確定後の fixture で確認する。
- 相対パスの基準が選択ワークスペースのルートになることを、複数ワークスペースの結合テストで確認する。
- `npm run check-types`、`npm run lint`、`npm test` を実行する。
- VS Code Extension Development Host で手動起動と通知のみの動作を確認する。

## リスク

HIGH

### 理由

複数の VS Code 起動経路とワークスペース境界を扱い、誤ったルートを選ぶと Git 差分・ソース位置・パス検証がすべて別リポジトリを参照するため。さらに設定ファイルの契約が未定義である。

## 対象外

- 入力 JSON 自体の構造・意味検証。
- Git の差分計算と commit 解決。
- Review Route、Tree View、差分 Webview の表示。

## 未確定事項

- `.vscode/change-viewer.json` が入力 JSON 本体なのか、入力ファイルの参照を持つ設定なのか。
- 「検出または更新」の更新操作をどのコマンド・イベントで行うのか。
- 入力 JSON 以外のアクティブ文書を選んだ場合の具体的なエラー UI。
