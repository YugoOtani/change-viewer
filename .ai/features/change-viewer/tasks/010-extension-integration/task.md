# タスク

## 目標

入力解決、検証、Git 読み込み、CU 照合、各表示先を拡張機能のコマンドとライフサイクルへ統合し、エラー・警告を仕様に沿って一貫して扱う。

## 背景

001〜009 は個別の境界・振る舞いを実装するタスクである。最後に、ユーザー操作からレビューセッションを生成し、入力エラーでは画面を開かず、Git 内容の警告ではレビューを継続し、各 VS Code リソースを dispose する経路を一つに統合する必要がある。

依存関係: 002〜009。共有状態・メッセージ・購読の最終接続を行うため、個別表示タスクを先に完了する。

## 受け入れ条件

- 手動コマンドと自動検出の入力を、対象ワークスペース解決 → 入力検証 → commit 解決・Git 読み込み → CU 照合 → 表示生成の順で処理する。
- 入力構造・commit 解決などレビュー開始前エラーでは Review Route、Tree View、差分 Webview を開かず、該当位置と理由を利用者へ伝える。
- Git 内容との不一致、存在しない親コード、無効な Route code step は警告として該当箇所に示し、他のレビュー表示を継続する。
- Review Route、Tree View、差分 Webview、通常エディタの選択状態が共通のレビューセッション ID と対象 ID で同期する。
- 再読み込み・再オープン時に古い Webview、Tree、選択状態、イベント購読が残らない。
- 拡張の activation / deactivation が登録コマンド、Tree provider、Webview provider、装飾、購読を正しく管理する。

## 必要な検証

- 正常入力、入力エラー、commit 不存在、CU 範囲不一致、無効な親コード参照を含む統合テストを追加する。
- 同一入力の再実行、表示中の再読み込み、複数ワークスペース切り替えで古い状態が混ざらないことを確認する。
- `npm run check-types`、`npm run lint`、`npm test` を実行する。
- Extension Development Host で、JSON からの起動、通知のみの自動検出、各表示間の選択同期、エラー時の未起動を確認する。

## リスク

HIGH

### 理由

複数のアーキテクチャ境界を接続するため、ライフサイクルやエラー経路の不備が個別には成功する機能を実運用で壊す可能性がある。

## 対象外

- 新しいレビュー仕様の追加。
- Git アルゴリズム、入力ルール、CU 照合ルールの変更。
- UI の細かな見た目の改善。
