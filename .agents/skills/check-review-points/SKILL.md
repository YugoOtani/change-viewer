# 目的
後続で人間のレビュアーが変更をレビューする際に一目では理解できない可能性がある箇所について、あらかじめ質問を投げかけるコメントを挿入する。質問はコードの動作や仕様の正しさを判断する必要はない。記述した質問は後続のレビュアーエージェントによって精査され、必要に応じて修正される。理解に詰まる箇所についてあらかじめ質問を投げかけることで、レビュアーのレビュー効率を向上させる。

# ルール
先入観なしでレビューを行うため、一切のスキルの使用および、仕様書以外のドキュメントの参照を禁止する。レビュー対象のコード差分のみを参照し、変更後のコードが一目で理解できるかどうかを判断する。
質問の個数を制限する必要はない。理解に詰まる箇所があれば、どこでも質問を残す。

# 手順
1. 変更差分を確認する
2. 変更差分の中で、このプロジェクトに初めて参加した新人エンジニアが一目では理解できない可能性がある箇所を特定する. 迷った場合は、後続のレビュアーエージェントが質問を精査するので、質問を残すことを優先する
3. 質問をASKから始まる行コメントとしてコード中に挿入する. 質問はコードの動作や仕様の正しさを判断する必要はない. 典型的には以下のような質問が考えられる
- ASK: この処理ブロック・関数は何をしているか
- ASK: この日本語はどういう意味なのか
- ASK: なぜこの実装なのか
- ASK: この処理ブロック・関数はなんのためにあるのか
- ASK: コメントに○○するとあるが、何が/何のために/いつ/どのように/どこで○○するのか
